# Scan Register Executable Build System

This directory contains the build system for creating a standalone executable for programming scan registers on IMCFlow hardware.

## Directory Structure

```
scan_executable_make/
├── CMakeLists.txt          # Main CMake build configuration
├── build.sh                # Build script
├── cmake/                  # CMake configuration files
│   ├── config_scan.cmake   # Scan-specific configuration
│   ├── config_arm.cmake    # ARM-specific settings
│   ├── config_x86.cmake    # x86-specific settings
│   └── arm-cortex-a53.cmake # ARM toolchain file
└── crt_config/             # CRT configuration (minimal, for compatibility)
    └── crt_config.h
```

## Prerequisites

1. **Generate scan kernel code first** using `scan_codegen.py`:
   ```bash
   cd /root/project/tvm/tvm_practice/test_imcflow/codegen/scan_gen
   python scan_codegen.py --run-policy-gen --scan-npz-dir <path_to_npz_files>
   ```
   This will create `build/program_scan_reg/program_scan_reg_kernel.cc` and associated `.host.o` files.

2. **Install dependencies**:
   - CMake >= 3.18
   - GCC/Clang compiler (for x86) or aarch64-linux-gnu-gcc (for ARM)
   - zlib library (static version preferred)

## Building the Executable

### For x86 (default):

```bash
cd scan_executable_make
mkdir -p build
cd build
cmake .. -DISA=X86 -C ../cmake/config_scan.cmake
make -j$(nproc)
```

Or use the build script:

```bash
cd scan_executable_make
./build.sh x86
```

### For ARM (cross-compilation):

```bash
cd scan_executable_make
./build.sh arm
```

## Output

The build will produce an executable:
- `build/program_scan_reg`

## Usage

Run the executable with the path to a directory containing NPZ files:

```bash
./build/program_scan_reg <scan_file_path>
```

Where `<scan_file_path>` is a directory containing NPZ files named:
- `imce_0_1.npz`, `imce_0_2.npz`, ..., `imce_0_4.npz`
- `imce_1_1.npz`, `imce_1_2.npz`, ..., `imce_1_4.npz`
- `imce_2_1.npz`, `imce_2_2.npz`, ..., `imce_2_4.npz`
- `imce_3_1.npz`, `imce_3_2.npz`, ..., `imce_3_4.npz`

(16 NPZ files total, one for each IMCE)

## Example

```bash
# Generate scan kernel code
cd /root/project/tvm/tvm_practice/test_imcflow/codegen/scan_gen
python scan_codegen.py --run-policy-gen --func-name program_scan_reg --scan-npz-dir ./scan_reg_files

# Build the executable
cd scan_executable_make
./build.sh x86

# Run the executable
./build/program_scan_reg ../scan_reg_files
```

## Build Options

### CMake Variables

- `ISA`: Target ISA (`ARM` or `X86`, default: `X86`)
- `SCAN_KERNEL_PATH`: Path to the scan kernel build directory (default: `../build/program_scan_reg`)
- `TVM_ROOT`: Path to TVM root directory (auto-detected or from `$TVM_ROOT`/`$TVM_HOME`)

### Custom Build Configuration

```bash
cmake .. \
  -DISA=X86 \
  -DSCAN_KERNEL_PATH=/custom/path/to/program_scan_reg \
  -DTVM_ROOT=/path/to/tvm
make -j$(nproc)
```

## Troubleshooting

### Error: "Scan kernel source not found"

Make sure you've run `scan_codegen.py` to generate the kernel source:
```bash
python scan_codegen.py --run-policy-gen --func-name program_scan_reg
```

### Error: "No host object files found"

The `.host.o` files contain binary data (policy tables, IMEM). They are generated by `scan_codegen.py` and should be in the same directory as `program_scan_reg_kernel.cc`.

### Error: "cnpy not found"

Make sure `TVM_ROOT` is set correctly and points to a TVM installation with the cnpy library in `3rdparty/cnpy`.

### Static zlib not found

Install the static zlib library:
- **Ubuntu/Debian**: `sudo apt-get install zlib1g-dev`
- **RHEL/CentOS**: `sudo yum install zlib-static`

## Notes

- The executable is statically linked for better portability and performance in gem5 simulation
- The build uses `-no-pie` and `-static-libgcc`/`-static-libstdc++` to reduce dynamic linker overhead
- The executable does not depend on TVM runtime components, only on cnpy for NPZ file loading
